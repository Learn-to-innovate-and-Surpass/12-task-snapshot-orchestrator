# 审核快照与单任务编排

把“看见了什么、审核了什么、实际提交什么、哪一次反馈可以核销”绑定起来，减少旧帧、错孔、重复反馈和重启续用旧抓姿造成的状态错误。

这是根据工程问题重新编写的离线参考实现，不是历史生产代码。所有演示使用合成身份和假抓姿引用，不包含控制器、相机、网络或运动接口。

## 快速运行

Python 3.10 或以上，无第三方依赖。在本仓库目录运行：

    python demo.py
    python -m unittest discover -s tests -v

演示在临时目录保存状态，退出后清理。测试覆盖冻结摘要、审核替换、单在途、完整反馈匹配、成功幂等、超时与晚到成功、重启和写入失败。

## 方法入口

- orchestrator.py：不可变 Target、Snapshot、Binding，以及 Orchestrator 状态机。
- demo.py：成功核销、重复成功、错孔反馈和重启的合成示例。
- METHODS.md：方法动机、状态变化、取舍和接入边界。
- tests/：独立的标准库测试。

审核后调用 freeze，得到包含帧号、场景版本、目标身份、目的孔、抓姿引用及输入内容摘要的快照。input_contents 要求传入实际审核的映射/假动作文件字节；逐文件内容 SHA-256 真正参与总快照摘要。dispatch 重新核对当前输入字节、帧和场景版本，同时显式传入总摘要。

本参考实现采用一帧一任务：每份快照只允许发出一个任务，发出后整帧失效；下一次任务必须重新观察和审核。这是便于验证恢复边界的保守示例，不是对原现场一帧多项串行批处理方案的复刻。

反馈必须完整匹配任务号、审核号、帧号、场景版本、线号、孔号和摘要。只有 COMPLETE 核销身份；相同成功反馈返回 DUPLICATE，不重复登记。错号、失败、超时及中断都进入复核，晚到成功不能改写原结果。

## 重启与持久化

状态文件只保存身份、已用帧、终态收据和复核记录，不保存抓姿引用或实际位姿。重启发现未结任务时，将它标记为 INTERRUPTED，禁止自动续发。人工核实实际结果后，resolve_after_review 才能解除阻塞；旧快照和旧帧仍不能使用。

状态采用同目录临时文件、flush、fsync 和原子替换。写入错误直接上抛，调用者不得继续向执行端提交。文件系统或硬件断电的完整恢复保证不在本示例范围内。

## 使用边界

一个状态文件由一个进程/实例独占写入。同一实例内部方法使用线程锁；本实现没有跨进程锁、分布式共识、通信认证或防篡改存储。不要同时打开两个编排器写同一个文件。

frame_id 必须由采集方为新曝光生成，scene_revision 必须由应用在场景变化时更新；这些字符串本身不能证明图像新鲜。读取文件时应将实际字节传给 input_contents，派发时重新读取并传给 current_input_contents。示例不监控磁盘文件，也不执行动作文件；实际调用者必须执行已核对内容，不能重新按同名路径读入未验证版本。超时仅使软件停止派发，不能证明设备已停止。人工“未完成”确认意味着现场已经核实没有需要保留的部分结果。

方法没有证明抓取成功、插入成功、碰撞安全或实时性能。接入实际系统时，还需要独立的设备反馈、现场停止和重新观察流程。
